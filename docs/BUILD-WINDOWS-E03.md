# Windows: подключение дополнительного E03 к комплекту E02

Дополнение даёт **файловый API E03** (один заранее обрезанный цикл). Не включает экран выбора упражнения, E03 live/Android или модель E01. Основной E02 A в базовом комплекте не заменяется. На этой машине уже работающие 8765/8870 не изменены. В приёмке использован отдельный loopback-порт.

## Историческая локальная сборка

Ниже — воспроизведение проверки на станции автора после `Get-FileHash -Algorithm SHA256 <файл>`:

| Архив | Размер, байт | SHA-256 |
|---|---:|---|
| `Qolda-Windows-Shared-WIP-7b88e3a.zip` | 2832739509 | `466af71d4424a18c617edc6c348f5ad07687c5021a79f2d6561db1260ddff795` |
| `Qolda-E03-File-Addon-v1.zip` | 232026 | `1860f895279afc3b80990a3dfc157c83b3928723bf87e6fc881351b981e79af4` |

1. В новую приватную папку вне Git распаковать оба архива. На одном уровне должны находиться `windows`, `engine-win64`, `e03-addon`. Требуются совместимый NVIDIA-драйвер и WebView2; Python, пакеты и модели отдельно не скачивать. Исходная копия дополнения: `deliverables/windows-e03-addon-v1/` в приватном дереве капитана.
2. На машине со **свободным** 8870 запустить `e03-addon\start-e02-e03.cmd`. Не считать старый процесс новым, если порт занят. Скрипт не останавливает службы. Обычный запуск одного `Qolda.exe` не подхватывает дополнительную модель.
3. Когда в терминале появится строка `SerIQ http://127.0.0.1:8870/; models: scratch`, проверить `Invoke-RestMethod http://127.0.0.1:8870/api/v1/exercises`: у E03 `readiness.windows.file` и `readiness.web.file` должны быть `true`. Затем `windows\Qolda.exe --attach-port 8870`. Если экран E03 ещё не подключён, это **не отказ файлового API**. Маршрут и поля результата: [контракт](contracts/extra-exercises.md).

## Что проверено

Из точной новой распаковки сначала использован прежний допуск только Web, затем **из распакованного готового дополнения** повторно открыты веса, FFprobe и штатный HTTP-обработчик общей сборки. Использован только изолированный Python комплекта, GPU RTX 5060 Ti. В одном процессе зарегистрированы E02 A и E03, E01 не зарегистрирован, E02 B отсутствует. На обоих прогонах два разрешённых validation-клипа E03 дали HTTP 200 `incomplete` / `complete`, а пустая сцена дала HTTP 200 `uncertain/low_visibility`; временный каталог пуст. После второго прогона каталог подтвердил E03 Web/Windows file, но не live/Android. Проверка не открывала окно EXE, не запускала `.cmd` на занятом порту и не была независимой проверкой на другом ноутбуке. На новом человеке качество не измерено.

Приватная квитанция `windows-e03-addon-v1/acceptance.json`: `5035fb5cc24a2d8a514f6988c7a705c516a08e013fd031849f101b56ea3d10e3`. Отдельный допуск: `cd1556c16b87167a56361e347f1656eff5a1a2af2e7f4638a48a71217b791e22`. Предыдущие веса и Web-only комплект не изменены. Для повторной упаковки **уже допущенного** набора: `python tools/pack_e03_windows_addon.py --approved-run <приватный-корень>/E03/run --out <приватная-папка>/addon.zip`. Упаковщик проверяет веса и метаданные, не создаёт допуск и не перезаписывает существующий архив. [Ограничения модели и baseline](../reports/ml/extra-e03.md).
