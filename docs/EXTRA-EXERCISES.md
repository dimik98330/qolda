# Qolda · E01 и E03: результаты и доступность

**E02 (разгибание локтя) остаётся основным упражнением приложения.** E01 и E03 — отдельные модели, не варианты A/B/C для E02. В этом репозитории есть код, агрегированные результаты и контракт, но нет весов или локальных допусков для E01/E03.

## Данные и модели

Исходные данные — [Mendeley Data V1](https://doi.org/10.17632/49h9dcwx5v.1), CC BY 4.0. В каждом клипе один размеченный цикл. Выборки готовятся отдельно для каждого упражнения, человек не пересекает train и validation в рамках упражнения. Неполный цикл и отказ от оценки — разные результаты.

| Упражнение | Train / validation | Модель | Baseline |
|---|---|---|---|
| **E01 · Поднятие предмета** | 82 / 21 клип; 4 / 1 человек | RTMPose для обеих рук, 48 фаз, временная CNN | Правило: подъём запястья и возврат; порог по train |
| **E03 · Разгибание запястья** | 81 / 20 клипов; 4 / 1 человек | CNN по разностям RGB-кадров (24 × 96 × 96) | Динамический baseline по движению в кадре |

[Паспорт данных](DATA-CARD.md) · [Подготовка выборок, обучение CUDA и команды повторной оценки](TRAINING.md)

## Что показала оценка

В таблице BA — средняя полнота двух классов. В прогонах с правом отказа отказ считается пропуском для истинного класса. Покрытие показано отдельно. Dev-валидация — один человек вне train для каждого упражнения. LOPO — четыре переобучения с нуля: на троих обучали, на четвёртом считали метрики; используются только клипы исходного train. Этот эксперимент проверяет перенос **рецепта**, а не опубликованные веса или точность на пациентах.

| Упражнение и протокол | BA модели / baseline | Решений модели / baseline |
|---|---:|---:|
| E01 · dev-валидация | 85,91% / 58,64% | 21/21 / 21/21 |
| E01 · LOPO, с отказами | 80,71% / 69,88% | 73/82 / 74/82 |
| E03 · dev-валидация, без отказов | 100% / 50% | 20/20 / 20/20 |
| E03 · LOPO, с отказами | 86,25% / 82,59% | 73/81 / 68/81 |
| E03 · LOPO, без отказов | 91,25% / 91,28% | 81/81 / 81/81 |

- **E01:** в отдельном переносимом файловом прогоне модель уверенно перепутала оба заранее выбранных примера. Это не новая оценка BA, но достаточная причина не включать режим в продукт. По движению руки нельзя доказать наличие предмета. [Отчёт](../reports/ml/extra-e01.md) · [агрегаты LOPO](../reports/ml/extra-e01-lopo.json).
- **E03:** без отказов CNN не превзошла динамический baseline. На самом трудном участнике CNN с отказами не распознала ни одного из 10 полных циклов: три ошибочные метки, семь отказов. 20/20 в исходной dev-валидации — результат другого, единственного участника; угол запястья не измеряется. [Отчёт](../reports/ml/extra-e03.md) · [агрегаты LOPO](../reports/ml/extra-e03-lopo.json).

## Платформы и допуск

| Поверхность | E01 | E03 |
|---|---|---|
| Web, локальный движок | Файловый маршрут реализован, режим не допущен | [Отдельный loopback-прогон](../reports/platforms/shared-wip-e03-file.md#дополнительные-упражнения-что-доступно): `complete`, `incomplete`, `uncertain/low_visibility` на пустой сцене. Не прогон браузерного экрана. |
| Windows | Не допущен | [То же файловое API проверено в изолированном Python приватного дополнения](BUILD-WINDOWS-E03.md#что-проверено): обе метки и отказ на пустой сцене. Окно EXE в этой проверке не открывали. |
| Android | Нет нативной модели в APK/AAR | Нет нативной модели в APK/AAR |
| Live-камера и штатный экран анализа | Не подключены | Не подключены |

Для чистого клона оба дополнительных режима по умолчанию выключены. `GET /api/v1/exercises` показывает независимую готовность по упражнению и платформе. Одиночный MP4/WebM (до 30 с и 64 МиБ) идёт в `POST /api/v1/exercises/E01/analyze` или `POST /api/v1/exercises/E03/analyze`. Для E03 локальный запуск требует собственных проверенных весов, GPU, отдельного допуска и приватного временного каталога; пример допущенного исторического прогона не является допуском новой сборки. Без настроенного движка анализ возвращает `503 model_unavailable`, а не ответ E02. Результаты дополнений не входят в дневной счётчик E02.
