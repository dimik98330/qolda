# Архитектура SerIQ · один анализатор для трёх поверхностей

> Требования хакатонного прототипа, а не подтверждение готовности.

`Инструкция → одиночная запись/файл → явное локальное согласие → декодер → pose+маска → ограниченный цикл → A или B → контроль уверенности → JSON v1 → сводка занятия`.

**Клиенты.** Общая веб-часть в `frontend/`; Windows-оболочка в `desktop/`, Android — в `android/`. Предпочтительный стек: небольшой TypeScript/Vite UI, Electron на Windows и Capacitor на Android; это выбор реализации, не требование импортировать эти зависимости для запуска Python-аудита. Два обязательных свойства оболочки: системный выбор видео и честное отображение состояния движка. Веб запускается на loopback-origin либо с доверенного локального dev-origin. Не открывать публичный эндпоинт для приёма видео.

**Вычисления.** Файл анализируется на компьютере команды/пользователя: `backend/api.py`, `backend/contract.py`; научный пайплайн и адаптер — `ml/`. На MVP Android может обращаться к тому же ПК по USB с явным согласием и `adb reverse tcp:8765 tcp:8765`. Интернет не является промежуточным звеном. Если достаточно производительный on-device экспорт ещё не проверен, эта поставка называется «APK + локальный движок на ПК», а не автономным Android. Не разрешать яснотекстовые сетевые обращения к произвольным адресам. Камера не обязательна при рабочей загрузке файла.

**Инференс.** Одинаковый экстрактор для A/B, одинаковые фильтры/маски, частота/ресемплинг указан в модели. Для каждого сустава хранить наблюдаемость. Нормализацию не подбирать с использованием ID или test. Полностью потерянная рука не превращается в нулевой угол. Для SLiM явно сопоставить источник и 25 суставов NTU; невидимая нижняя часть тела — ограничение переноса. Экспорт и CPU-переносимость — отдельные проверяемые результаты. Доказательство обучения B — изменение исходных обучаемых весов, не наличие предобученного pose-детектора.

**Локальные данные.** Сырые видео и временные массивы остаются вне Git. Backend не ведёт журнал содержимого, не отправляет телеметрию; обработку ограничивают размер/тип/длительность и число одновременных запросов. Нет аккаунта, пациентской БД или внешнего API. Клиент собирает только текущую сводку без идентификатора человека; после очистки состояние исчезает. Версия HTTP, семантика ошибок и фикстуры — `docs/contracts/api.md`, `docs/contracts/ui.md`, `fixtures/contracts/`.

**Потери и отказоустойчивость:** недоступная модель → 503; плохое наблюдение → uncertain/no_pose; прерванная передача → повтор той же попытки без двойного счёта; не читает камера → файл; недоступно устройство → честная отметка в отчёте. Не перескакивать незаметно на подставные ответы или облако. Для демонстрации выбрать A/B по validation прежде, чем отсматривать test. В примерах интерфейса не подставлять test-клип из архива организатора.
